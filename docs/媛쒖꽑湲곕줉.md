## v0.4 (2026-11-24): Vercel 이전 + 보안 강화

**받은 피드백 (교수님)**
- 구글 시트가 느림 → Vercel 사용 추천
- 조건 없이 남의 프로필을 열람할 수 있음 → 적합도 높을 때만 노출 / 닉네임 / 가입 시 동의

**반영한 내용**
- 백엔드 이전: 구글 시트(Apps Script) → Vercel 서버 함수 + Postgres (속도 개선, GitHub 푸시 시 자동 배포)
  - 화면 코드는 데이터 계층(RD.api)만 /api/rpc 로 바꿔 거의 그대로 재사용
- 보안: 가입 시 공개 동의(필수), 실명 대신 닉네임, 프로필 공개범위(전체/적합도 높을 때만/비공개)
- 열람 제한: 매칭은 적합도 임계값(기본 45점) 이상만 기본 노출, 비공개 프로필은 서버에서 제외, 상세 소개는 연결된 연구자에게만
- 짜잘한 기능: 비밀번호 변경, 닉네임 변경(기존 팀·요청 표시 이름도 자동 갱신)

**다음 주에 확인해 볼 것**
- Vercel 배포 후 실제 응답 속도가 체감되게 빨라졌는지
- 적합도 임계값(45점)이 적당한지 — 너무 높으면 아무도 안 보이고, 낮으면 열람 제한 효과가 약함
- 닉네임만으로 팀원 간 식별이 충분한지
- 연구 경험 단계 명칭(탐색·참여·주도) 확정

## v0.3 (2026-11-17): 킬러 기능 집중

**받은 피드백 (교수님)**
- 그룹을 유연하게 확장: 외부인의 참여 요청 + 멤버의 초대
- 지원자가 여럿이면 비교·선택할 수 있는 정보 제공
- 가진 능력 ≠ 이 프로젝트에 쓰고 싶은 능력 → 기여 의향(역할·시간·계획) 반영
- 킬러 기능을 정해 하나를 처음부터 끝까지 완성
- “레벨 1~5”는 서열처럼 보일 수 있음 → 중립적인 표현 논의

**실사용으로 찾은 문제 (v0.2)**
1. 거절 사유를 직접 쓸 수 없음 2. 커피챗 일정이 일방적으로 확정됨 3. 학부·대학원·교수 역량 차이가 안 보임
4. 그룹 결성 후 할 수 있는 게 없음 5. 요청 시 어느 그룹으로 들어가는지 모름

**반영한 내용**
- 킬러 기능 정의: 자리 → 기여 의향 지원 → 지원자 비교 → 팀 공간 확장·소통 → 완료·후기
- 기여 의향서, 지원자 비교 화면, 그룹 = 프로젝트 팀 통합(대상 팀 선택), 팀 공간
- 커피챗 양방향 조율, 거절 사유 직접 작성, 회원 구분 배지 + 연구 경험 단계(탐색·참여·주도, 이름은 팀 논의 후 확정)
- 일부러 제외: 실시간 채팅·파일 공유·일정 관리 (카카오톡·드라이브로 대체, 팀 메시지 + 오픈채팅 링크로 최소 지원)

## v0.2 (2026-11-10): 피드백 반영

**받은 피드백**
- 데이터는 스프레드시트(또는 Vercel)로 저장해서 다른 사람 컴퓨터에서도 보이게
- 가상의 학생 18명보다 팀원 6명의 실제 프로필로
- 매칭 카테고리를 1인 1개씩 골라 총 6개로 시작 → 잘 되면 늘리기

**반영한 내용**
- 로그인·회원가입 추가, 프로필·요청을 구글 스프레드시트(Apps Script)에 저장
- 더미 연구자 삭제 → 팀원 가입 후 실제 프로필로 매칭
- 매칭 카테고리 6개: ① 관심 주제 ② 연구 역량 ③ 경험 ④ 학과·전공 ⑤ 목표 성과 ⑥ 협업 조건 (카테고리마다 파일 분리)
- v0.1 문제 보완: 연구 주제 유사성 반영(①), 목표 성과 단계화(⑤), 중요 카테고리 2배 반영 기능
- 받은 요청함: 상대가 직접 수락·거절 (v0.1의 시뮬레이션 버튼 제거)

**이번 주에 확인해 볼 것**
- 팀원 6명끼리 매칭했을 때 결과가 직관과 맞는가? (“이 사람이 왜 1위지?”)
- 카테고리별 규칙(점수 배분)이 담당자가 의도한 대로 나오는가?
- 프로필 입력 항목이 많아서 귀찮지 않은가?
- 응답이 느리지 않은가? (스프레드시트 서버라 1~3초 걸림)
